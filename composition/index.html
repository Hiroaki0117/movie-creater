01はじめに

HyperFrames は、HTML を動画のソース形式に変える

HTML / CSS / JavaScript で組んだ画面に時間軸を与えると、それがそのまま MP4 になる。動画編集ソフトではなく、動画のためのレンダリングエンジンです。

index.html
→
hyperframes render
→
out.mp4
02セットアップ

必要なのは Node 22+ と FFmpeg、あとは npx だけ

npx hyperframes init my-video — プロジェクトを作る
npx hyperframes preview — ライブリロード付きで確認する
npx hyperframes render — MP4 に書き出す（FFmpeg が要る）
03構造

コンポジションは、ルート1つとクリップの集合でできている

<div data-composition-id="root" data-duration="10">   ← 出力の尺
  <div class="clip" data-start="0" data-duration="5"
       data-track-index="1">タイトル</div>      ← 表示される部品
</div>

時間を持つ要素には class="clip" が必須です。これが無いと、フレームワークが表示・非表示を制御できません。

04タイミング

3つの data-* 属性だけで、時間軸が決まる

data-start
いつ現れるか。コンポジションの先頭からの秒数で指定します。
data-duration
何秒映るか。ルートに付けたときは、出力全体の尺になります。
data-track-index
どのレイヤーに乗るか。数字が大きいほど手前に描かれます。
05トラック

トラックは重なり順、クリップは表示区間を決める

track-index 3
ロゴ
track-index 2
見出しテキスト
track-index 1
背景

同じトラックで時間が重なると z-index の解決が必要になります。重ねたい要素は、 別のトラックに分けるのが基本です。

06アニメーション

アニメーションは、paused な GSAP タイムライン1本に集約する 

const tl = gsap.timeline({ paused: true });
tl.to("#title", { opacity: 1, y: 0, duration: 0.6 }, 0.5);
window.__timelines["root"] = tl;   ← キーはルートの id

再生するのはエンジン側です。自分で play() は呼びません。タイムラインはページ読み込み時に同期的に作ること — async や setTimeout の中で組むと、レンダラーが先にサンプリングしてしまいます。

07決定論

レンダラーは時刻を渡してフレームを取り出す。だから時計も乱数も使えない

Date.now() / performance.now()
レンダー時の時計。フレームごとに違う値を返してしまいます。
種なしの Math.random()
ばらつきが要るときは、シード付きの擬似乱数を使います。
repeat: -1
無限ループ。尺から有限回を計算して渡します。

MP4 に書き出す。publish で共有リンクも作れます。
09おわりに

HTML が書ければ、動画が書ける

このスライド自体も、1枚の HyperFrames コンポジションとして書かれています。 composition/index.html を開けば、いま見ている画面のソースがそのまま読めます。

↳決定論の詳細 1 / 2

1フレームは、時刻だけから再現できなければならない

レンダラーに「再生」という概念はありません。どのフレームも、毎回まっさらな seek として描かれます。しかも並列にサンプリングされるので、順番通りに来る保証も ありません。前のフレームを通ってきたことを前提にした状態は、必ず壊れます。

↳決定論の詳細 2 / 2

時計や乱数は、タイムライン上のトゥイーンに置き換える

// 無限ループは、尺から有限回を計算して渡す
repeat: Math.max(0, Math.floor(duration / cycle) - 1)

// ceil は data-duration を超えて lint に弾かれる

setTimeout や requestAnimationFrame に手が伸びたら、それはタイムライン上の トゥイーンとして書き直すべきサインです。
