# HyperFrames のスキルをどう使い、何が作れるのか

## 第1部 — 一言から MP4 が出るまでの流れ

HyperFrames はエージェント前提で設計されている。人間が仕様を覚えて書くのではなく、
やりたいことを一言渡すと、エージェントが決まった順路をたどって成果物まで運ぶ。

順路は次のとおり。

1. **/hyperframes に投げる。** これが唯一の入口。「動画を作りたい」でも
   「このスライドを直して」でも、まずここに来る。
2. **意図が確認される。** 何を伝える動画なのか、どこに置くのか、どのくらいの長さか。
   フォーマットが決まっていない依頼なら、切り口の案がいくつか提示される。
3. **BRIEF.md が書かれる。** 確定した答えが 1 枚のファイルになる。以降このファイルが
   唯一の正で、同じことは二度聞かれない。セッションが切れても再開できる。
4. **ワークフローが選ばれる。** 入力の種類が出力を決める。URL なら製品紹介、
   GitHub の PR ならコード解説、音楽ならビート同期、テキストなら解説動画。
5. **ストーリーボードが組まれる。** シーン割り、ナレーション原稿、各シーンの尺。
6. **フレームが作られる。** 1 シーン 1 ファイルの HTML として組み上がる。
7. **check が走る。** lint・実行時エラー・レイアウト崩れ・モーション・
   文字コントラストを一括で検証する。ここを通らないと次に行かない。
8. **render で MP4 が出る。**

覚えるべき手順はない。止まるべき場所でエージェントが止まり、聞くべきことを聞く。

## 第2部 — 何が作れるのか

入力の種類がワークフローを決める。

- **product-launch-video** — 製品サイトの URL やブリーフ → 製品紹介・機能訴求の動画。
- **faceless-explainer** — 記事・メモ・お題のテキスト → 解説動画。素材が無くても
  タイポグラフィと図で成立させる。この動画がまさにこれ。
- **pr-to-video** — GitHub の PR → コード変更の解説動画。差分とコミットから組む。
- **motion-graphics** — 10 秒前後の短尺。ロゴのスティング、数字のカウントアップ、
  グラフの一撃、字幕オーバーレイ。ナレーション無しで動きだけで見せる。
- **slideshow** — プレゼン・ピッチデッキ。段階表示、ホットスポットからの分岐、
  発表者モード。出力は MP4 ではなく操作できるデッキ。
- **music-to-video** — 音源 → ビート同期の映像。リリックビデオやスライドショー。
- **embedded-captions** — 既存のトーキングヘッド映像 → 字幕を載せる。映像は無加工。
- **talking-head-recut** — 既存の映像 → 情報カードやローワーサードを重ねる。
- **general-video** — 上記に当てはまらないもの全般。長尺、モンタージュ、
  ブランドリール。共同編集モードもここ。

## 締め

この動画自体、テキストを一つ渡しただけで組み上がった faceless-explainer の出力。
HTML で書かれていて、ソースを開けばそのまま読める。
